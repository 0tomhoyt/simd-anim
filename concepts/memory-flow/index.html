Reading the picture

  1. Prefetch spends bandwidth to buy latency

    pldl2keep pulls the next B page into L2 on HBM's budget while FMOPAs run, so the loop's own loads never wait. pldl1strm streams C lines through L1 without evicting resident data. Nothing here is free — every prefetch is a bet that the bandwidth is cheaper than the stall.

  2. The store drains across kernels

    st1w touches only the L1-resident aligned buffer; stnt1w then writes memory non-temporally — no read-for-ownership, no doubling. That drain outlives the kernel call: it overlaps the next kernel's pack reads, and for one slot HBM serves 64 B of read plus 64 B of write at once. That contention is exactly what the multi-threaded pipeline phases absorb.

  3. Compute is the quiet part

    FMOPA slots move zero bytes: once the operands are in registers, the compute leaves every meter at rest. All the drama on this page is supply-side. The budgets are unigemm_sme's measured tiers; on a real machine C is far larger than 64 B, so the drain spans many k groups — the mechanics are exactly these.

Bytes are labelled per hop; budgets are per 8-cycle slot.
