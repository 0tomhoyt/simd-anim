Reading the picture

  1. The smallest honest picture

    The real kernel runs a 2 × 2 grid of tiles covering 32 × 32, four FMOPAs per k group, four load slots. Everything here is the same choreography, scaled down — one 4 × 4 tile, two k groups — so you can follow every single value. One shortcut is worth naming: the drawn tile starts at zero, so the loop only accumulates — a real kernel must clear ZA first (zero {za}) before its first FMOPA.

  2. Transpose is absorbed by pack

    Only the highlighted read pattern changes: gather takes one element per source row (row-strided ld1w, transposed in the ZA), copy takes one contiguous run (ldnt1w). Both produce the same panels, so the tagged core — the loop — never learns which layout you chose.

  3. Software pipelining

    Each load slot carries one k group; in the real kernel there are four, with pldl2keep pulling B into L2 and pldl1strm streaming C. A leftover K tail runs its own small ldr + fmopa loop, and C leaves through st1w slices plus a non-temporal stnt1w flush.

  4. Words this page borrows

    rank-1 layer — one outer product: a single A column times a single B row, one k's contribution added to every cell of C at once. k-major — K runs contiguously, one k per drawn panel column. mul vl — the byte length of one scalable vector at the current SVL (16 B here), so [pa, #1, mul vl] is the next vector along. non-temporal — a store that goes straight to memory without first fetching the line it overwrites (no read-for-ownership). w12 picks the ZA row a store cuts out; p0 is the predicate saying which of its four words are written.

A and B hold small integers; C = A × B.
